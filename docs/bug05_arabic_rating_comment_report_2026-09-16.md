# BUG-05 Arabic Rating Comment Input Report

تاريخ التنفيذ: 2026-09-16. نطاق العمل: تعليق تقييم السائق واختبار ترميزه وطوله؛ لا تعديل لنماذج أخرى أو بيانات قاعدة الإنتاج.

## Root Cause

**لم تُثبت فرضية وجود فلتر ASCII في التطبيق الحالي.** الحقل في `DriverRatingBottomSheet` هو TextField عادي دون inputFormatters أو استبدال للحروف، بـmaxLines=4 وmaxLength=500. اتجاهه موروث من لغة التطبيق، ويُحذف الفراغ الخارجي فقط عند الإرسال.

قبل تعديل أي كود إنتاجي، نجحت اختبارات إدخال العربية وإرسالها كما هي. ثم أُدخلت الجملة «التوصيل ممتاز والسائق ملتزم» في النموذج الحقيقي على المحاكي، وظهرت كاملة والعداد **27/500**. أكد المستخدم أنه كان يستخدم كيبورد الكمبيوتر وأن الحروف لا تظهر أصلًا معه.

هذه الأدلة تحصر المشكلة المبلغ عنها على الأرجح في مسار إدخال كيبورد الكمبيوتر إلى المحاكي، وليس حظر Unicode في الحقل أو API. لم تُلتقط أحداث كيبورد المستخدم الخام ولم تُغيّر إعداداته، لذلك لا نجزم بإعداد معيّن أو عيب في إصدار محدد من المحاكي. وثائق [محاكاة الكيبورد من Android](https://android.googlesource.com/platform/external/qemu/+/master/docs/ANDROID-KEYBOARD-EMULATION.TXT) تشرح اعتماد تحويل أحداث الكيبورد على character mapping؛ هذا سياق تقني وليس إثباتًا لإعداد الجهاز الحالي.

**خلل منفصل مؤكّد في الطول:** Flutter يحسب grapheme clusters، بينما API كان يستخدم `mb_strlen`. مثلًا `عَ` مكررة 500 مرة تُعرض 500/500 في Flutter، لكن السيرفر كان يحسبها 1000 ويمنع إرسالها. هذا لا يفسر اختفاء الحروف أثناء الكتابة، لكنه اختلاف حقيقي ضمن متطلبات BUG-05 وتم تصحيحه.

## Flutter Fix

لم يُعدّل حقل Flutter ولا خدمة إرسال التقييم؛ المقارنة مع نسخة بداية المهمة تؤكد أنهما مطابقان. لا يوجد formatter قديم لإزالته. بقيت الاختيارية وتعدد الأسطر والـRTL والحد 500 والسلوك المترجم كما هي.

أُضيفت اختبارات تثبّت قبول العربية والإنجليزية والمزيج والأرقام والمسافات والترقيم والحركات والإيموجي. اختبارات HTTP تستخدم MockClient وتعترض الطلب قبل الشبكة؛ النص يصل URL-encoded باستخدام UTF-8 دون تغييره أو إرسال هوية العميل في body.

لإدخال العربية يدويًا على المحاكي، استخدم لوحة Android العربية بدل الاعتماد على تغيير لغة كيبورد الكمبيوتر وحدها. يمكن إضافة العربية من Gboard → Languages → Add keyboard، ثم تبديل اللغة من لوحة المفاتيح، وفق [تعليمات Google الرسمية](https://support.google.com/gboard/answer/7068494?hl=en). لم أُجرِ تغيير إعدادات الكيبورد نيابة عن المستخدم ولم أُعد اختبار ضغطاته الفيزيائية بعد ذلك.

## Duplicate Rating Verification

قاعدة العمل الحالية هي **تقييم واحد لكل عميل + سائق** (`driver_id` + `rater_id`)، وليست تقييمًا مستقلًا لكل شحنة. هذه نقطة مهمة؛ لم نغيّرها أو نضيف shipment_id إلى جدول التقييمات.

داخل transaction يتم قفل صف السائق بـFOR UPDATE ثم فحص التقييم السابق قبل INSERT؛ التكرار يعيد DRIVER_ALREADY_RATED/409. وتوجد آلية request ID لمنع تكرار الطلب نفسه. هذه المسارات مطابقة لنسخة بداية المهمة.

اختبار Widget يثبت تعطيل الإرسال أثناء الطلب؛ اختبارات Widget/Service تحافظ على رسالة رفض التكرار وعدم اعتبارها نجاحًا. لم يُرسل تقييم إنتاجي ثانٍ لاختبار الرفض ولم يُحذف التقييم المسجل لإعادة الاختبار.
